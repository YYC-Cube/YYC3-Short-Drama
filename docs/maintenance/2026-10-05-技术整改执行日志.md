## 步骤 3：认证双栈收敛 + 登录缺陷修复 + 演示模式标注 ✅

**日期**：2026-10-05 ｜ **状态**：已完成 ｜ **问题编号**：P0-3（关联 P1：auth-context 未 memo、`{}` 真值缺陷）

### 架构决策

**静态轨为当前唯一交付形态 → 认证收敛为 mock 单源**：

- 唯一数据源：`services/auth-service`（本机模拟）；`contexts/auth-context` 不再 `fetch("/api/*")`
- 修复的核心缺陷：旧流程 `single-page-auth` 先调 mock `loginUser`（成功）→ 再经 context 调真实 `/api/auth/login`（静态站 404）→ 必然抛错报"登录失败"。现收敛为**单一调用链**：页面 → context → service
- 全栈轨恢复时的切换点唯一化：只需替换 `auth-context` 内部实现（已写入代码注释）

### 变更清单

| 文件 | 变更 |
|---|---|
| `contexts/auth-context.tsx` | ① 全面改用 auth-service；② `login/register` 返回服务响应（页面组装提示）；③ `normalizeUser` 严格判空（修复 200-空 user → "已认证空对象"缺陷）；④ Provider value `useMemo` + 全部方法 `useCallback`（消除全树级联重渲染）；⑤ 挂载恢复用 `loadCurrentUser` 纯函数 + cancelled 守卫（通过 react-hooks/set-state-in-effect 新规则）；⑥ 移除 context 内部的导航与 1.5s 硬编码延时（导航职责归还页面） |
| `components/auth/single-page-auth.tsx` | ① 登录：删除双重调用，单次 `await login(...)`；② 注册：改走 `context.register`（透传邮箱/密码），消灭直接引用服务层的旁路；③ 错误提示展示真实 `error.message`；④ 新增"演示模式"标注区块（如实告知账号数据仅存本机） |
| `services/auth-service.ts` | （行为补齐，未改代码）`loginUser` 的持久化职责移入 context 的 `persistSession`，`getUserInfo` 从 localStorage 恢复——登录→刷新页面→保持登录 现在闭环可用 |

### 消费者兼容性验证

逐一 grep 全部 `useAuth()` 消费者实际使用的字段（`username/name/phoneNumber/avatar/isLocalUser/level/tongbao`），归一化映射全覆盖；`register` 原签名零调用方，扩展了可选 `details` 参数（向后兼容）。
